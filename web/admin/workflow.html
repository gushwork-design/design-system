3

Where nothing verifies the result

The same system seen from the library’s side. One spine — everything is measured, drawn on the sheet, and passes your review before it reaches the skill.

  1. 1
    Nothing diffs Figma against the measured exports

    The pull is manual, so a changed value in Figma goes unnoticed until someone re-measures that node. The badge ruling is the live proof: the decision moved light labels to /600, Figma still ships /500, and the system has held both positions for weeks without complaint. Not yet built.

  2. 2
    The gate can only pass what it draws, and it draws part of the library

    The review sheet now states its own coverage at the top, counted rather than typed — 11 of 18 groups rendered, 19 further sets named and not drawn. Under the new routing that is a throughput limit, not a display gap: a set the sheet cannot draw is one you cannot review, and therefore one that cannot enter the skill.

  3. 3
    Work built here takes the same spine now, but nothing carries it

    Ruled 15 September: anything built directly in Claude Code is measured into exports/*.md like anything else, drawn on the review sheet, and enters the skill only once you have reviewed and passed it. No side door. What the ruling lacks is a mechanism — both steps are manual today, which is why the route is dashed and still numbered.

  4. 4
    The font rule was absolute in a target that cannot obey it

    Closed. foundation/output-targets.md said never to let a build fall back, and also said to emit a standalone file for mockups — which cannot load a licensed face at all. A rule right half the time gets followed at random. It is now a per-target table, and scripts/check-fonts.sh enforces it row by row.

What runs today

scripts/_sheet_coverage.py stamps the review sheet’s coverage at publish time · scripts/check-drift.sh --unstamped lists builds carrying no stamp, so absence is the alert · scripts/check-fonts.sh <path> --target <row> enforces the font table. Gaps 1 and 3 remain open.
