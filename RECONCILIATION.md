# Reconciliation — master specification vs. measured Figma

> **4 Oct 2026.** The dashboard set this file reconciles (2.4–2.7, 2.10: the dashboard button, avatar,
> header and sidebar, toast, KPI card and table row) was retired and rebuilt from the design hub; see
> `exports/dashboard/README.md`. Those sections are kept as the record of why the measured set was
> trusted over the spec. The ruling that blue fills are banned on dashboards still stands.

Two sources describe this design system and they disagree.

- **Measured** — values read through the Figma MCP off specific nodes: variant names from
  `get_metadata`, real CSS from `get_design_context`, colours from `get_variable_defs`,
  appearance from component renders. Every claim traceable to a node ID.
- **Spec** — the *Gushwork Design System Master Specification* (6 Aug 2026), generated by the
  Figma agent.

Where they agree, the exports state it once. Where they disagree, **the exports follow the
measured value and this file records the conflict.** A measured node is what actually
renders; a spec is a description of it.

---

## Rulings — Utsav, 6 Aug 2026

**1. There is no second component library.** Only `↳ web/ pattern-library` holds the navbar
and the button. `↳ web/ component-library` does not contain a second set.

This settles almost everything below, and not in the spec's favour. The "two components,
document both" theory is dead. Where the spec describes a navbar, page-build, dashboard
button, avatar, header, sidebar, toast, KPI card or table row that does not match the
measured node, **the spec is describing something that is not in this file.** Measured wins
in every case. Do not merge those sections.

**2. Blue fills are banned on dashboards.** Confirmed. The measured rule stands; the spec's
`Blue` dashboard-button style is rejected. Action tiers on the product surface are
`Primary` (black) / `Outline` / `Ghost`. Blue remains valid as a signal — Info toasts, blue
badges, the progress-bar track — the ban is on button fills.

**3. Content width is 1240.** The measured value wins over the `1400` token and the spec's
`~1280`. Side margins are 100px in a 1440 page.

### What ruling 1 implies for the rest of the spec

The spec's structural claims were checkable in nine places and **wrong in all nine**. It is
therefore not a trusted source for anything not independently measured. Two consequences:

- The detail in spec §13 and §15 for components that *do* exist — Badge, tooltip, the input
  set, the card types, controls, toast — is **plausible but unverified**. Merge it only after
  measuring the node.
- Several components the spec documents have **never been found in the file at all**:
  `Modal` (§15.8), `Empty State` (§15.9), `Dropdown Menu` (§15.10), `Notification Badge`
  (§15.11), `Segmented Control`, `Breadcrumbs`, `Date Picker`, and `Pagination` as a
  standalone component. Treat every one as **not verified to exist.** Building from them is
  exactly the invent-a-component failure the fallback rule exists to prevent — if a request
  needs one, fall back rather than build it.

## Part 2 — Where they conflict — RULED

**All four are settled by one standing rule: where a measured component and the written spec
disagree, the measurement wins.** `DECISIONS.md` → **R0**.

The spec describes an intended system; the file *is* the system. These four are not near-misses —
the navbar differs in variant count, prop names and fill, and the dashboard button spec proposes
a blue style that does not exist. Building to the spec produces screens that match nothing anyone
opens in Figma.

**R0 settles spec-vs-Figma, not Figma-vs-sense.** A measured value that is wrong on its own terms
— off-palette, failing contrast, internally inconsistent — is still a defect, and R6, R7, R9 and
R10 each override one.

The detail below is the record of what differed.

### 2.1 Variant key spacing — spec normalises load-bearing keys

Spec writes `Outlined/black`, `Outlined/white`, `Text/black`. The actual component names are:

```
Outlined/ black      space after the slash only
Outlined / white     spaces both sides
Text/ black          space after the slash only
```

Measured from `get_metadata` on `1457:668`. **These are keys.** The normalised forms will not
resolve. Exports keep the irregular spacing.

### 2.2 Navbar — two different components

| | Measured (`1706:1799`) | Spec (§14.1) |
|---|---|---|
| Variants | 8 | 4 |
| Props | `Breakpoint` · `State` (6 values) · `Type` (Brand\|Ads) | `Device` · `Darkmode` (On\|Off) |
| Fill | `--gw-color-neutral-25` (`#F7F8F9`) | `#FFFFFF` or `#0D0D0D` |
| Padding | 100px side margins | `16 80 16 80` |
| Nav items | Who It's For · Platform · Solutions · Customers · Pricing | generic "TEXT links × N" |
| CTAs | one — `Book a Demo` | two — "Login" (Outlined) + "Get Started" (Blue) |

Not a discrepancy in detail — a different component. There is no `Darkmode` property on the
measured navbar and no `State` property on the spec's.

### 2.3 Page Build

Measured `1735:61598`: **8 variants**, `Breakpoint` · `Type` (Brand\|Ads) · `Blank` (no\|yes).
Spec §14.12: **2 variants**, `Device` only.

`Type` is the axis both SKILL.md files are built around — it drives navbar, footer and every
button colour. The spec has no equivalent.

### 2.4 Dashboard button — the spec proposes a blue one

| | Measured (`2203:931`) | Spec (§15.1) |
|---|---|---|
| Variants | 108 | 56 |
| `Style` | `Primary` · `Outline` · `Ghost` | `Blue` · `Black` · `Outlined` |
| `Size` | Small · Medium · Large | Small · Medium |
| Heights | 28 / 44 / 48 | 36 / 40 |

**This one is a governance conflict, not just a data one.** The dashboard rule annotation
(`2205:15688`, `2177:11486`) says *"Never use a blue fill on dashboards — the tiers here are
black / outlined / text only."* The spec gives the dashboard button a `Blue` style as its
primary. Both skills currently encode the ban.

### 2.5 Dashboard avatar

Measured `1658:24023`: 16 variants — `Style` (1\|2\|3) × `Color` (Blue\|Red\|Yellow\|Green\|Orange)
× `Admin`. A generated character: coloured body rect, head rect, face-cutout vector, `r:4`.

Spec §15.2: 18 variants — `size` (16\|20\|24\|32\|40\|72) × `user` (Image\|Initials\|Icon),
circular, `radius = size/2`.

Nothing in common. The spec's avatar is a conventional user avatar; the measured one is an
illustrated character with a reserved admin variant.

### 2.6 Dashboard header and sidebar

| | Measured | Spec (§15.5) |
|---|---|---|
| Header size | 1164 × 164 | 56px tall |
| Header padding | `40 40 20 40` | `0 24` |
| Header title | 32px Vert Grotesk Semibold (`Heading/h5`) | Inter SemiBold 16px |
| Header contents | tabs + 3 filter dropdowns + refresh & timestamp | breadcrumbs, bell, avatar, settings |
| Rail width | **260**, `--gw-radius-20`, gap 60 | 240 expanded / 56 collapsed, `borderRight` |

The measured header is a page header. The spec's is an app top bar. They are not the same
element, and the spec's dashboard also has no collapsed-rail state in the measured file.

### 2.7 Toast

Measured: `Error` · `Warning` · `Success` · `Info`; the rule leaves auto-dismiss **explicitly
undefined**, and the export says not to pick a timeout.

Spec §15.3: `Success` · `Error` · `Warning` · `Undo` · `Offline`; auto-dismiss 5s except
Error/Undo; width 360 fixed; bottom-right stacked.

`Info` vs `Undo`/`Offline` is a real fork. The spec answers the dismissal question the file
deliberately left open.

### 2.8 Hero and CTA copy

Spec §14.3 says the hero is "always Blue primary CTA". Measured `fold/ Hero` has
`Layout` = Home \| Centered \| `+ Create New` \| Split \| Form, and primary colour follows
`page-build`'s `Type` — Brand pages take `Black`.

Spec §13.1 uses **"Get Started"** and **"Submit"** as the example primary CTAs. That
contradicts the `Book a Demo` ruling of 6 Aug 2026 in `foundation/voice.md`. Treated as
generic placeholder text, not a copy change.

### 2.9 Content width — three values

| Value | Source |
|---|---|
| **1240** | measured off both worked `page-build` instances on `↳ web/ template-library` |
| 1400 | `--gw-bp-content-width`, Breakpoint collection |
| ~1280 | spec §14 prose, "max content width ~1280px centered in 1440" |

Exports document 1240 — the only one measured off a real composition. Likewise side padding:
measured 100px vs spec's 80px.

### 2.10 KPI card and table row

- **KPI card** — measured props `Mode` × `Type` (only 6 of 18 combinations built). Spec §15.6:
  `Trend` (Up\|Down\|Neutral) × `Size` (Default\|Compact), value Inter SemiBold 28px.
- **Table row** — measured `Type` (Header\|Data) × `State` (Default\|Hover\|Select-enabled\|Selected).
  Spec §15.7: `Type` (Header\|Row\|Selected) × `Density` (Default\|Compact).

### 2.11 Icon count

Spec: 1,249 sets. Exports: 1,248. Trivial, but it means one of the two counted a
non-icon set — plausibly one of the three still named `component_set-element`.

## Part 3 — Pages never reachable through the MCP

The spec lists eight pages:

```
00 · Cover · 00 · Playground
01 · Core       → building-blocks · shared-components
02 · Web        → component-library (21 sets) · pattern-library (32 sets) · template-library
03 · Dashboard  → component+pattern-library (17 sets)
04 · Slides
```

**`get_metadata` with no node ID returns only `00 · Cover`.** Individual nodes on other pages
resolve fine when addressed directly — `1658:24112` (dashboard) and the `↳ web/ pattern-library`
nodes all read correctly — but the page list itself never enumerates. This is consistent with
the stray U+2028 LINE SEPARATOR characters that already break whole-page metadata reads.

Consequence: **`↳ web/ component-library` was never read.** Everything in exports/web/ comes
from `↳ web/ pattern-library`. So spec §13.1–13.7 — Badge, tooltip, the seven input
components, the six card types, processing indicators — may describe a library that genuinely
exists and that the exports have simply never seen.

**That is the most likely explanation for §2.2 and §2.4:** two navbars and two button sets,
one per library page, and the exports captured the pattern-library one. If so, both are right
and the exports are incomplete rather than wrong.

## Lead-magnet document — Sep 2026

The lead-magnet template was built against the installed plugin's older `colors_and_type.css`
and then ported onto `foundation/tokens.css`. Colour and radius were mapped **by resolved hex**,
not by name, because the two sheets are different palettes whose scales are offset — the old
sheet's `neutral-500` is this repo's `neutral-400`. Four disagreements survived the mapping.

**1. The hairline. Repo wins, and the old value was wrong.** The template used `#e1e3e8`; no
token carries it. It is now `--gw-color-neutral-100` `#e7e8e9`. That is not merely the nearest
match — it is the value the Figma cover chip uses for its own `0.5pt` border, so the port
corrected a drift rather than approximating one. Nine uses.

**2. The interior ground. Repo wins.** The template used `#fafbfb`, the old sheet's
`neutral-25`. This repo's `neutral-25` is `#f7f8f9`, and the supplied page-layout reference
matches `#f7f8f9`. Built as `--gw-color-neutral-25`.

**3. The type ramp is not tokenised — measurement wins.** `--gw-text-*` is px-based for web.
The cover and closer are laid out in `pt` to sit 1:1 on their Figma frames; `56pt` is not
`56px`, and consuming the tokens there would shrink every heading by a quarter. Interior body
also runs `16px/1.6` rather than the token's `16px/24px` because page fit is tuned to that
leading. The template declares its print ramp as template-local `--lm-*`; everything `--gw-*`
in it is a real system token.

**4. The closer's blueprint grid is an override, not a measurement.** Frame `1769:3965` is flat
`#0d0d0d` — sampled, zero hits on the grid lattice the cover lights up. The grid is carried onto
the closer anyway, on Utsav's instruction, so the two dark pages match. Recorded here so it is
not "corrected" back to the frame later.

Two measured facts worth keeping with these:

- The closer's button label **renders at ~18pt** though the frame binds `Body/body-16-med`.
  Measured 13% wider than 16pt produces. Built at 18pt, which lands the button at exactly
  246×44. Measurement wins over the variable list.
- The bundled Inter renders **~3.7% narrower** than Figma at the same size — an `opsz`/version
  difference, Inter-specific; Vert Grotesk matches at ratio 1.000. Left alone: it is invisible
  in ragged-right copy, and compensating would break every other page.
